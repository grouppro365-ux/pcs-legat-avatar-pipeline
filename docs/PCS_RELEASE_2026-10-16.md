## Что изменилось

- Четыре вспомогательных API проверяют конкретное разрешение на договор, документы/OCR, цены или настройки бота; активной сессии недостаточно.
- Расчёт договора использует канонический баланс с валютой/возвратами и отдельным обеспечительным депозитом. Сбой или противоречивый баланс блокирует генерацию.
- Прямой переход аренды проверяет текущий договор, объект, клиента, даты и реальные сохранённые подтверждения; завершение запрещено при нерешённой проблеме. Переход и аудит записываются одной SQL-командой с проверкой версии.
- WhatsApp/Instagram/Facebook intake использует сохранённый UUID runtime-контакта и входящее сообщение проверенного адаптера. Нечёткое объединение по имени/телефону запрещено. Telegram сохраняет существующий provisioner.
- Channel send сохраняет квитанцию до истории; восстановление записи истории не повторяет сообщение. Неизвестный исход передаётся оператору. Повтор сверяет исходную команду, в том числе после конкурентного завершения.
- Meta ingress, генерация и dispatch используют устойчивые идентификаторы и плановое восстановление. Политика канала проверяется заново; выдуманная confidence удалена. Неподтверждённая свободная AI-генерация остаётся черновиком.
- Retry worker восстанавливает прерванные безопасные задачи и использует постоянные курсоры с CAS для Meta/бронирований. Частота cron не приводит к пропуску страниц. Старый процесс не перезаписывает новую попытку.
- Отчёт «Источники и результаты» связывает сохранённый источник с каноническими профилями. Клиентские VERIFIED gross переводы и ожидаемая комиссия показаны раздельно, по валютам. Нет придуманного ROI или смешения клиентских денег с доходом PCS.

## Проверка

- 851 автоматический тест: `rg --files -g '*.test.mjs' -0 | xargs -0 node --test`.
- `contract-api-source.cjs`, `contract-files-source.cjs`, синтаксис изменённых браузерных скриптов и `git diff --check` — успешно.
- QA Neon: канонический intake, replay/collision, blocked/merged, Telegram-регрессия; отдельный переход аренды с атомарным аудитом; полный существующий service execution/portal/payment/capacity/offer withdrawal набор — реальные SQL-прогоны с откатом.
- Независимая проверка прав/финансов/аренды/коммуникаций; обнаруженные P1 и P2 исправлены. После последней небольшой правки обхода бронирований пройден отдельный regression и общий набор.
- Production read-only HTTP: authorize-purpose разрешённая цель 200; неизвестная цель и внедрённые permissions 400; attribution-report 200, `unavailable=[]` (на выбранном периоде привязок нет).
- Восемь Edge Functions повторно прочитаны после deploy: файлы совпадают побайтно. Расхождения старого remote baseline с Git были только пробельными; посторонний код не затёрт.
- Существующий плановый retry-worker активен каждую минуту. Его HTTP-результат после релиза прочитан из сохранённой очереди: 200. Ручной запуск worker не выполнялся.

Frontend включён в тот же Git-релиз: отчёт открывается из финансов и доступен сотрудникам только с `settlements.view` + `audit.view`. Публикация Vercel и точные хеши публичных ресурсов проверяются после merge.

## Границы

Клиентские сообщения, реальные платежи/бронь и приватные документы не создавались для production-проверок. Browser/Telegram UI E2E не выполнялся согласно прежнему исключению пользователя. Межканальная проверка владения для объединения аккаунтов, LINE intake, универсальная квалификация/клиентский follow-up и полный контентно-видеоконтур остаются открытыми. Платёжные интеграции исключены: сохранённые реквизиты и ручная проверка оплаты.
